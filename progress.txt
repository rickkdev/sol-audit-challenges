# Ralph Progress Log
## Codebase Patterns
- Python CLI code uses a `src/sol_audit_challenges/` package layout with Typer commands exposed through the `sol-audit-challenges` console script in `pyproject.toml`.
- Use `.venv/bin/python -m pytest` after installing `.[dev]` locally to run the pytest suite against the editable package.
- JSON schema validation lives in `src/sol_audit_challenges/validation.py`; CLI validation commands should report both the input file path and a `#/...` schema location for failures.
- Prepared case outputs are split into `<output-dir>/public/<case-id>/source` for distributable source snapshots and `<output-dir>/private/` for draft oracle files.
- Sanitization lives in `src/sol_audit_challenges/sanitize.py`; replacement reports should include labels, replacement values, counts, and file paths, but never the sensitive `find` strings from sanitizer config.
- Bundling lives in `src/sol_audit_challenges/bundle.py`; public archives are deterministic `tar.gz` files under `bundles/<case-id>.tar.gz`, contain files below a `source/` prefix, and update public manifests with relative package paths plus SHA-256 checksums.
- Running lives in `src/sol_audit_challenges/run.py`; `run-case` validates bundle checksums, exposes only `source/` and `public-manifest.json` in the tool workspace, and writes persistent run artifacts under `<output-dir>/runs/<case-id>/<run-id>/`.
- Submitted finding report validation uses `schemas/submitted-report.schema.json` and the `validate-report` CLI command; committed examples should stay fake and live under `examples/submitted-reports/`.
- Scoring lives in `src/sol_audit_challenges/score.py`; `score-report` uses deterministic location and keyword signals and should not print raw private oracle origin/sources or accepted-finding text by default.
- Private candidate research and oracle data should stay in ignored `research/local/` or `ground-truth/` paths; committed `templates/` files are placeholders to copy before adding real source references, vulnerable commits, or incident identifiers.
- Leakage auditing lives in `src/sol_audit_challenges/leakage.py`; `audit-leakage` scans source directories, files, and tar archives, with optional private JSON denylist terms kept in ignored paths such as `research/local/` or `*.denylist.json`.
- Complete fake end-to-end benchmark fixtures should live under `examples/fixtures/`; committed fake oracle examples can use `.oracle.example.json` so they validate without conflicting with ignored real `*.private.json` or `*.oracle.json` paths.
